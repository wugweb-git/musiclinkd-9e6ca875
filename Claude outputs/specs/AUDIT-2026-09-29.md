## Two facts that shape everything

**1. The Android shell loads the live site over https.** `capacitor.config.ts` sets `server.url`
rather than bundling assets, because every route is server-rendered by Nitro and nothing is
prerendered. In the config's own words: *the app needs a connection to start; there is no offline
first paint yet* — and a web deploy reaches the app with no store release. So **network latency is
the app's startup time**, and offline behaviour is a product gap, not a bug.

**2. There is already a design system, and it is documented.** `src/styles.css` defines 191 custom
properties in an `@theme inline` block; `docs/token-scale-spec-2026-09-16.md` describes three layers
(primitive → semantic → component) and names Storybook's Tokens page as the tiebreaker;
`docs/system-rules-2026-09-16.md` names the canonical components. The UI half of this audit is
therefore **conformance against an existing system**, not a new visual direction.

Installed Capacitor plugins: `android` · `app` · `browser` · `core` · `push-notifications` ·
`splash-screen` · `status-bar`. An `android/` project exists.

## A — Mobile, Capacitor, performance

### A1 · Android hardware back is not handled anywhere — critical

`grep -rn "backButton\|hardwareBackPress" src/` returns **0**. `@capacitor/app` is imported only for
`appUrlOpen` (`src/lib/native-auth.ts:71`). The sheet listens for **Escape only**
(`src/components/ml/ui.tsx:769-772`), and Android's back button does not synthesise Escape in a
WebView.

There are **82 overlay call sites**, 41 of them the custom `Sheet`. Back-to-dismiss is the universal
Android reflex; here it pops history, leaves the screen and loses the sheet's form state. Making
every "+ new" a drawer multiplied this.

### A2 · `TopBar` has no top safe-area inset, and it is used 158 times — critical

`src/components/ml/ui.tsx:331` — `sticky top-0 … px-5 py-4`, no `env(safe-area-inset-top)`.
`viewport-fit=cover` **is** set (`src/routes/__root.tsx:87-93`) and `targetSdkVersion = 36`
(`android/variables.gradle:4`) forces edge-to-edge on Android 15+, so the inset is non-zero and
nothing consumes it: back arrow and title sit under the status bar.

Same at `tab-icon.tsx:155`, `onboarding.tsx:511`, `search.index.tsx:331`,
`marketplace/index.tsx:133`. Only `home.tsx:216` and `identity.qr.tsx:100` do it right.
**Bottom insets: 18 sites correct. Top insets: 4 in the whole repo.**

### A3 · Camera QR scan cannot work in the wrap — critical

`src/routes/identity.scan.tsx:125` calls `getUserMedia`; `AndroidManifest.xml:60` declares **only**
`INTERNET`. No `CAMERA` permission, no `@capacitor/camera`, no barcode plugin. The catch branch
lands on `setPhase("error")`. **Unverified on device**, but the manifest makes it near-certain. The
`capture="environment"` file-input fallback at `identity.scan.tsx:187` does work.

### A4 · Push notifications are entirely dead code

`src/lib/push.ts` exports `registerForPush` / `pushAvailable` / `clearDeliveredPushes` — **zero call
sites** outside the file. `saveMyPushToken` (`src/lib/push.functions.ts:21`) — zero call sites. The
plugin is registered natively and `google-services.json` exists, so the whole chain is built and
never invoked. No `pushNotificationReceived` listener, so a tapped notification would not deep-link.
No `POST_NOTIFICATIONS` in the manifest, so the Android 13+ prompt has nothing to request.

### A5 · GSAP ships on every screen for one 0.2 s tween

`src/components/ml/kit.tsx:10-11` imports `gsap` at module scope; `kit.tsx` is pulled by `ui.tsx:44`,
which is on every screen. Verified in the build: `ui-SncQIlIk.js` is **193 KB raw / 66 KB gzip** and
contains the GSAP runtime. Its only use is a scale+opacity tween at `kit.tsx:248-259` that a CSS
keyframe already in `styles.css` could do. ~50 KB gzip parsed on first paint.

### A6 · `new QueryClient()` with no defaults — 136 `useQuery`, 6 `staleTime`

`src/router.tsx:8`. Default `staleTime: 0` plus refetch-on-focus plus refetch-on-mount, so every tab
switch and every resume from background refires the server function. Compounded at
`src/router.tsx:14-16`: `defaultPreload: "intent"` with `defaultPreloadStaleTime: 0` means the loader
that ran on touch-intent is **already stale** when the navigation commits — **two server calls per
navigation**.

### A7 · `useAuth()` is a bare hook, not a context — 91 independent sessions

`src/hooks/use-auth.ts:5-24`: every call runs its own `getSession()` and `onAuthStateChange`
subscription. **91 call sites** across 84 files, including `__root.tsx:153` and nine hooks that fan
out further. Every auth event produces 91 `setSession` calls and 91 new object identities.
`BottomNav` is in that path (`ui.tsx:213`), so it runs in the persistent shell.

### A8 · Full supabase-js including realtime on the critical path, realtime never used

`use-auth-DOcX74ih.js` = 214 KB raw / **55 KB gzip**, 23 realtime matches.
`grep -rn "\.channel(\|postgres_changes"` → **0 hits**. The client needs GoTrue and storage only;
280 `createServerFn` definitions do the data work server-side.

### A9 · No image pipeline at all

- **No resize or compress before upload** — `src/lib/profile-images.ts:27-31` only *validates*;
  limits are 5–10 MB (`profile-images.ts:13-16`, `listing-photos.ts:12`, `studio-photos.ts:13`). A
  phone camera JPEG is 4–8 MB and is uploaded verbatim.
- **No CDN transform** — `getPublicUrl` only; no `?width=`, no `/render/image`.
- Those originals render into `h-6 w-6` avatars (`booking.tsx:954`), `h-11 w-11`
  (`opportunity.tsx:192`), `h-12 w-12` (`rental.tsx:95`).
- **99 `<img>`, 5 with an explicit width.** Corrected while fixing this: only **33** lack a fixed
  box once Tailwind classes are counted — the other 61 are already pinned by `h-*`/`w-*`,
  `aspect-*` or `absolute inset-0`, so they cannot shift. The CLS exposure is a third of what the
  first pass claimed. **52 with `loading="lazy"`** → ~47 without.

On metered 4G this is the app's biggest data cost and a guaranteed CLS source.

### A10 · Remote-URL shell, no offline path, splash hides before content

`capacitor.config.ts:26-33` — cold start is launcher → splash → **network SSR fetch** → ~294 KB gzip
critical path → hydrate. `SplashScreen` sets no `launchShowDuration` (defaults 500 ms) and nothing
calls `SplashScreen.hide()`, so the user sees a flat `#ECECF1` window for the rest of the fetch. No
service worker.

### A — also found

**Plugin reality.** `status-bar` installed, never imported, no config block. `splash-screen`
configured natively, no JS control. `app` used only for `appUrlOpen`. `@capacitor/haptics` is **not
installed** though `src/lib/haptics.ts:3` says it should be.

**Manifest permissions missing for code that exists:** `CAMERA`, `POST_NOTIFICATIONS`, `VIBRATE`
(`haptics.ts:18` `navigator.vibrate`, silently swallowed), `ACCESS_*_LOCATION` (`market.tsx:803`).
Also `allowBackup="true"` with no rules, so session tokens get backed up.

**Web APIs that silently fail in a WebView:** `window.open` for Directions
(`booking-actions.ts:68`); `a.download` for the `.ics` (`booking-actions.ts:56-60`) — **and it
toasts "Calendar event downloaded" regardless at `:63`**; the `.vcf`
(`identity.contact.save.tsx:53`); **the data-export JSON** (`settings.privacy.tsx:153`), which is a
DPDP-style "download my data" flow; the QR PNG (`qr.tsx:32`). `navigator.share` is not implemented
in Android WebView, so every share button silently becomes a copy button. **`@capacitor/browser` is
already installed** and would fix the first of these today.

**Touch targets.** `src/components/ui/button.tsx:20-25` — every variant is under the 44 px floor
(`default` 36, `sm` 32, `lg` 40, `icon` 36×36). A correct `hit-area` utility exists
(`styles.css:964-978`) and is used at 39 sites; the shadcn `Button` never uses it.

**`100vh` in the primary sheet.** `ui.tsx:792` `max-h-[88vh]` on the component used at 41 sites;
should be `dvh`. Also `drawer-list.tsx:166`, `onboarding.tsx:1185`, `marketplace/l.$id.tsx:257`.

**Dead weight.** `src/components/ui/chart.tsx:2` does `import * as RechartsPrimitive from "recharts"`
and is **imported by nothing** — a landmine that would pull all of recharts into whatever chunk first
touches it. `src/styles/liquefy-ui.css` is 93 KB and imported nowhere.

**Home bypasses React Query entirely** (`home.tsx:74-107`, `useState` + `useEffect`), so returning to
the most-navigated tab always re-fetches and always shows a spinner.

**Unbounded serial awaits.** `collabs.functions.ts:215-217` (N invites = N round-trips),
`verification.functions.ts:427-434` (serial storage copies).

## B — Accessibility and design-system consistency

**Better than expected in three ways**, which narrows where the real defects are: every `<img>` in
all 308 `.tsx` files has an `alt`; only 3 interactive non-semantic elements exist, none in `ml/`; and
`text-muted-foreground` on `bg-subtle` measures ≈16.4:1 — the contrast worry in the brief does not
hold, because `--muted-foreground` was already darkened.

| | Finding | Impact |
|---|---|---|
| **B1** | **`Field` gives its control no accessible name — 106 call sites, ~70 unnamed.** The visible label is a `<span id>` inside `role="group"` (`listing-form.tsx:278-309`), so the name lands on the wrapper, never the input. | A screen-reader user hears "edit text, blank" on most of Hire, Create-listing, Post-opportunity and Verification. **One fix to one component repairs ~70 controls.** |
| **B2** | **Field errors are never tied to the control.** `role="alert"` fires once on insert; the whole app has **4 `aria-describedby`** and 8 `aria-invalid`. | Tab back to a bad field and you hear nothing. |
| **B3** | **`Sheet` — the only modal, 119 uses — has no focus trap and no scroll lock.** Escape and focus restore are there; Tab containment, `inert` and body scroll-lock are not. **`kit.tsx:734` states the opposite in a comment**, which will keep the bug alive. | Tab walks into the page behind the modal. |
| **B4** | **`IconBtn` silently drops `aria-expanded` / `aria-controls`** — it destructures a fixed prop set with no rest spread (`ui.tsx:665`), and hyphenated JSX attributes escape excess-property checks. | Every collapsible profile section announces as a plain button. |
| **B5** | **`Segmented` is a broken tab pattern on 24 screens** — `role="tablist"` with no `aria-controls`, no `tabpanel`, no arrow keys. | Honest fix: drop the ARIA roles rather than half-implement them. |
| **B6** | **The `Switch` off-state is invisible** — track and thumb are both `bg-background`, contrast **1:1** (`kit.tsx:421`). | Used on the two screens that are nothing but switches. One-line fix. |
| **B7** | **Brand pink as a text background in the two places the system forbids** — `market.tsx:1156` (≈3.56:1) and `tab-header.tsx:42` (≈3.4:1). | Both are 10–11 px bold count badges where the number *is* the information. `styles.css:596` documents the rule and `--brand-button` exists. |
| **B8** | **Touch targets** — `SaveButton` is 36×36 and sits on every list row; `gallery.tsx:268` remove-✕ is **24×24**; the ProductCard heart ≈23×23. | A correct `hit-area` utility exists and is used at 39 sites out of hundreds. |
| **B9** | **`Loading` announces nothing** — `aria-busy` on a bare div, 57 usages. | Every list loads silently. The right shape already exists at `profile.tsx:330` (`role="status"`). |

### Design-system drift

`ProductCard` (`market.tsx:325-459`) is **a second design system**: four raw hexes, Tailwind's
`red-500`, `cqw` radii and type, an 11 px floor, a hand-rolled shadow.

- **57 hand-written reproductions of `<Card>`** against 139 real uses — 29% copy-paste.
- The radius scale **declares 4 steps and has 10 in use**; Opportunities has quietly standardised on
  `rounded-[20px]`, which does not exist in the scale.
- `Btn variant="brand"` has **zero call sites**, because the two places that need it hand-roll it.
- Four field patterns, four switches, six list-row shapes. `filter-sheet.tsx` is 106 lines with zero
  imports from the system.

**The systematic gap is the error state.** ~14 screens have a query, a `Loading` and an `EmptyState`
but **no `isError` branch**, so a network failure renders "You haven't written any reviews yet."
`StateCard tone="error"` exists and is simply not reached for.

## C — Flows, journeys, architecture

### C1 · `/booking/$id` renders a hard dead end

No `Screen`, no `TopBar`, no nav, no link (`booking-context.tsx:96-107`). Triggered by a bad slug
**or by a real studio with no rooms configured**, since `getResource` returns undefined for an empty
`resources` array. On Android the only escape is the system back gesture.

### C2 · A talent can offer a service and receive enquiries, but cannot see them

`sendEnquiry` writes `business_profile_id = the service owner`, talent or business, and `listMyLeads`
reads it back correctly — but `/leads` is hard-gated by `useRequireBusiness` (`leads.tsx:82`). The
row is written and never shown, and `/leads` is in the menu for talent accounts, so they see it and
hit a wall. **The gate is tighter than the data requires.**

### C3 · A seller's rental inbox is polluted by their own rentals

`rentals.functions.ts:188` filters on an embedded column **without `!inner`**, which in PostgREST
nulls the embed instead of restricting the parent. Two other call sites in the same file get it right
(`:393`, `:477`), so it is a mistake, not a choice. RLS prevents a leak; the effect is blank-titled
cards and an inflated "Open requests" count on `/marketplace/mine`.

### C4 · Every multi-step flow except onboarding keeps state in `useState`

Booking, rental request, collab, band, sell, business-new. Refresh or deep-link and the draft is
gone. Sharpest case: a signed-out buyer who fills in a whole booking is sent to `/welcome`, which has
no return parameter, and lands on `/discover` with the booking lost
(`booking.$id.review.tsx:162`). **Onboarding is the model to copy** — URL step, server-persisted
answers, and a coherent screen for a step that no longer applies.

### C5 · Zero route-level auth; four client-side gating shapes

Nothing is exposed — every server function carries `requireSupabaseAuth` and RLS backs the tables —
but four shapes means four signed-out experiences, and the `useEffect` redirect flashes the owner
screen first.

### C6 · 192 `throw new Error(error.message)` in server functions, 40 surfaced verbatim

Via `toast.error(e.message)`. Raw Postgres and zod strings reach users.

### C7 · 15 orphan routes

Genuinely stranded functionality: `/help/category/$key`, `/reviews/$id/edit` (you can write and
report a review but never edit one), `/marketplace/nearby`. Also `bands.$id.portfolio.tsx` has an
unconditional redirect followed by **130 lines that can never run**.

### C8 · Type safety is clean on `any` (zero) but leans on 136 `as never`

The dangerous form is on **writes** (`collabs.functions.ts:183-204`), where a mistyped column
compiles silently.

## Regressions — already fixed

Three breakages from the screen consolidation, found by this audit and shipped in `9988255`:

- **R1** — repointing `/portfolio/new` at `/portfolio?add=1` dropped `from: "onboarding"`, so
  `onboarding_complete` (written only at `onboarding/complete.tsx:62`) was never set and every new
  talent account was permanently mid-onboarding. Answers persisted, so no data was lost.
- **R2** — the collab wizard opened on "Plan" because the removed Kind step left a `type ? 1 : 0`
  offset, so Details, the only step holding `name`, never rendered.
- **R3** — two Settings rows pointed at deleted routes; the `as LinkProps["to"]` cast hid it.

Plus the 7 stale `/studio` links, including Discover's "Studios → See All" self-loop and the share
link on a confirmed booking, which shared the redirect stub instead of the studio booked.

## One copy inconsistency, noted not fixed

Screen titles are mostly sentence case — "Add a link to a live set", "Ask for another time" — with
Title Case outliers such as **"Apply through Messaging"**. There are **no written brand guidelines**
in `docs/` or `Claude outputs/` to enforce against; the voice is real but implicit in the copy.
Deriving the guide from existing copy would settle this, and is a separate piece of work.
