## Headline

- **42 tables**, not the ~5 touched opportunistically earlier this session.
- **`bands` is not a table — it's `collabs` filtered by type.** `bands.functions.ts`'s
  `listBands`/`getBandBySlug` query `.from("collabs")` directly. `band_events`,
  `band_members`, `band_releases` are views over `collab_events`/`collab_members`/
  `collab_releases` the same way (present in `information_schema.columns`, absent
  from `information_schema.tables ... table_type = 'BASE TABLE'`). One schema,
  two product concepts (`collabs.type` presumably distinguishes them).
- **`collabs` now has a real schema** (`collabs`, `collab_events`, `collab_members`,
  `collab_releases`) — as of `supabase/migrations/20260917120000_collabs.sql`,
  sitting uncommitted in the working tree as of this writing. Earlier this
  session I said the collab feature had zero backend; that was true when
  checked, and is no longer true. `src/routes/collab*.tsx` still render
  entirely from `@/data/collab` seed data — nothing in the app queries these
  tables yet.
- **Two tables have zero references anywhere in the app**: `feed_posts` and
  `cms_pages`. Not a single `.from("feed_posts")` or `.from("cms_pages")` in
  `src/`. Either dead schema or built ahead of a feature that hasn't landed —
  worth asking rather than assuming either way.
- **`portfolio_item_plays` is fully wired but invisible to a naive `.from()` grep**
  — written via the `record_portfolio_play` RPC (`src/lib/plays.ts`), read via
  the `trending_portfolio_items` RPC (`src/lib/trending.functions.ts`, the
  function wired to `discover.music.tsx` and `discover.index.tsx` earlier
  today). Real, working, just RPC-shaped rather than direct-table-shaped.

## Table-by-table

referencing that table in `src/`, not what plausibly should. Where a column
list is long, only the columns that matter for understanding the shape are

wasn't worth transcribing in full here.
