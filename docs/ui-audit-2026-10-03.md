# MusicLinkd product UI audit — 3 Oct 2026

## Scope

All 143 route files and the shared authentication, onboarding, navigation, identity, discovery,
work, network, commercial, and utility systems were reviewed against the supplied references,
owner-supplied logo, and Brand OS.

## Findings

- The token foundation is disciplined, accessible, and should remain the source of truth.
- The product feels recycled because most routes share the same narrow title-and-card stack.
- Mobile behavior is robust, but the former 640px desktop canvas created excessive dead space.
- Real media leads in profiles and Market but is underused in services, QR identity, work
  management, and onboarding handoffs.
- Settings has the clearest grouped-list language; similar operational lists hand-roll weaker rows.
- Talent, business, and band profiles need one verified signal and owner-action pattern while
  keeping genuinely distinct information architecture.
- Search has three interaction patterns across work and network routes.
- The Connections navigation label and Messages page title describe one destination differently.

## Direction

The system borrows Lovable's mechanism, not its literal palette: disciplined neutral ground,
assertive ink, one concentrated expressive moment, confident typography, and energy through
interaction. Pink remains a rare signal; real music-industry media carries colour.

The first shared implementation applies the supplied logo, a wider bounded desktop canvas,
media-led authentication, contextual headers, white elevated surfaces, editorial empty/error
states, and content-shaped loading states. Route-family composition work can now proceed without
creating another parallel design system or changing data contracts.
